# Topology Prompt Orchestrator

采用渐进式披露流程，按以下阶段逐层输出。每阶段输出后等待用户确认或修改。

快速通道：当用户需求已非常完整且复杂度低（节点数 <= 3）时，可跳过中间阶段直接输出最终完整 prompt。

## Phase 1: topology_overview — 拓扑概要

输出内容：
- 站点数量与角色（如：部门1、部门2等）
- 每站点的设备类型与数量
- 业务网段概要（可用默认网段，如 10.1.x.0/24）
- 互联方式（IPsec VPN / GRE / 直连等）
- 上网策略（本地 WAN 出口 / 集中出口）

输出格式（必须使用）：
```
## 拓扑概要

**站点与设备：**
- ...

**业务网段：**
- ...

**互联方式：** ...
**上网策略：** ...
```

规则：
- 当用户未指定具体 IP 时，自动分配合理默认网段，不要为此发起澄清。
- 仅当存在真正歧义（如站点数量不确定、设备角色不清）时才提出一个澄清问题（使用 `clarify_options`）。

## Phase 2: node_and_link_plan — 节点与链路清单

基于已确认的拓扑概要，输出：
- `## 节点清单` — 每个节点的名称、模板、所属站点
- `## 链路清单` — 每条链路的两端节点与端口

规则：
- 节点命名需包含站点前缀（如 HQ-FGT、BR-FGT）
- 端口编号必须明确，不得使用模糊表述
- 用户可在此阶段调整节点数量或连线关系

## Phase 3: execution_steps — 执行步骤与规则

基于已确认的节点和链路清单，输出：
- `## 执行步骤` — 完整的步骤序列（创建节点 → 创建链路 → 启动 → 等待就绪 → 配置 → 验证）
- `## 执行规则` — 步骤间的顺序约束和注意事项
- `## CRITICAL: 部署完成检查清单` — 与步骤一一对应的验证项

规则：
- 步骤中必须包含完整的设备配置命令块（CLI 配置内联在步骤中，不得省略）
- 必须包含 wait_for_nodes_ready 等待步骤
- 步骤编号、执行规则和检查清单数量必须一致
- FortiGate 场景须包含 configure_node 动作

## Phase 4: completed — 合并输出

将所有已确认的层合并为最终可执行 prompt，包含完整 5 个章节且顺序一致：
1. `## 节点清单`
2. `## 链路清单`
3. `## 执行步骤`
4. `## 执行规则`
5. `## CRITICAL: 部署完成检查清单`

输出规范：
- 仅输出最终 prompt 正文，不得夹带解释性废话
- 内容必须可执行，不得有空泛描述
- 不得在一次响应中同时输出多个澄清问题
